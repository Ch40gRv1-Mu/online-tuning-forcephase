# 计算节点与worker并行调度

日期：2026-11-04。这里的node指计算节点。用户已明确要求agent和node并行；本文件仅制定调度计划，未连接服务器、扩容或执行采集。新增节点尚未提供。

## 一实验一owner，多节点执行

- 一个中央owner拥有协议版本、任务清单、预算和状态机；多个agent只提交独占产物/候选，不各自重建一套求解队列。
- 每节点一个执行器从中央清单领取任务，在该节点的可用CPU槽位启动worker。不同节点领取不同实例任务。
- 静态任务只补缺失CNF特征；动态任务每题只采一个固定D前缀、总进程2CPU秒/10秒墙钟，不重建TA的终局耗时标签。
- gate与最终测试默认不进入任何worker清单。一个最终候选冻结后，才由中央owner建立唯一gate清单。

## 资源决定并发，不能按agent数量倍增

现有节点的历史资源记录是8vCPU、16GiB内存；短探针profile为1.5GiB地址空间/worker、1GiB临时证明/worker、12GiB磁盘底线。启动前读取当前可用量及既有任务占用；静态提取器按其原3GiB上限独立规划。

对节点n计算新增动态槽位：

`new_slots[n] = min(free_pinned_cpus, floor(spare_memory/1.5GiB), floor(max(0, free_disk−12GiB−outstanding_unused_proof_reserve)/1GiB))`

- `spare_memory`扣除系统余量、既有任务及在途检查器/提取器需求；1.5GiB限制相加不是总RSS一定安全的证明。
- 磁盘的`free_disk`已经反映当前写入文件，不再重复扣已写证明；只扣在途证明cap尚未使用的预留，防止旧式重复计算导致错误停止。
- 静态提取槽位使用3GiB/worker和正式实施记录的输出空间；它与动态槽位共用同一CPU、RAM、磁盘账本。
- 校验器、序列化及传输的真实费用和占用也计入执行；不能在8个solver之外无约束再开8个checker。
- 若现有8路健康队列已占满CPU，新增槽位为0。复用其产物并等待释放；不抢占、不重启、不启动第二owner。

## 单节点与多节点配置

|情形|执行方式|约束|
|---|---|---|
|只有当前8vCPU节点|空闲时最多8个短探针，静态提取按内存减并发；本地可同时进行离线拟合/聚类|所有worker共用一份预算与资源账本|
|提供第二个合格节点|中央owner按剩余任务动态分配，两节点同时领取不同任务|记录节点硬件、solver/observer身份、实际资源，不声称已扩容|
|提供更多节点|按各节点实际槽位汇总吞吐；新节点先完成必要的实现资格与输入身份步骤|不增加实例数、种子、探针时限或全项目CPU预算|

32个agent不会把一个8核节点变成32核。可并行的任务总量由真实空闲节点资源决定；本地拟合/聚类也应限制内部BLAS线程，避免每进程各占满CPU。

## Claim与checkpoint契约

1. 冻结任务manifest与源码后，中央owner用事务性队列表登记`task_key`、role、input_sha、method_sha、seed、预算、node、pid、attempt、状态和费用。
2. `task_key`绑定输入、静态提取器或solver/observer、观测点、资源/验证profile、seed和预算；node/CPU硬件信息另记，任何不兼容身份不作同测量复用。
3. 状态为`PENDING → CLAIMED → RUNNING → COMPLETE/FAILED/UNKNOWN`。领取使用中央原子事务/唯一键；跨节点不能仅依赖各机器自己的flock。
4. worker写独立临时产物，完成后原子发布不可变结果及SHA；owner校验身份、完整性与必要model/proof记录后提交COMPLETE。完成一题就checkpoint，不覆盖原记录。
5. 心跳中断、SSH失败、租约过期仅标UNKNOWN，不自动退回PENDING。先取得原进程已终止及任务确未完成的权威证据，才按版本化恢复协议补缺。
6. FAILED保留错误和实际CPU；恢复产生新attempt/身份关联，不把失败改写成普通timeout或删除费用。

## 固定块与统计屏障

- 动态首块仍是原顺序24fit＋16feedback共40题；可以跨节点乱序完成，但必须40题完整检查后判断覆盖是否≥20，不能依据先完成的题评分。
- 覆盖合格才分配其余最多152题；已完成首块逐条SHA复用，绝不重跑凑完整矩阵。
- 静态/动态可并行准备，完整所需产物齐备后才评价相应候选。所有节点合并回原全部父题人口，失败/不可用按协议回退，不删慢题。
- 跨节点CPU速率不同，动态统计和探针成本按节点分列；TA wall标签保持原来源。不能直接将不同硬件的绝对计时混成同一精度的成本。

## 预算与速度

192个主探针上限为384CPU秒；8个实际空闲槽位的理想工作量约48秒，16槽位约24秒，均不含解析之外的准备、传输、验证和工程。实际短任务常受启动/数据传输支配，因此不承诺节点翻倍就总耗时减半。

动态开发阶段≤1CPU核时、全项目≤100CPU核时是所有节点合计；失败、验证、工程和必要重试均计入。各节点不能各领一份1核时预算。owner以实际去重物理费用＋在途预留控制新领取量。
