# 多agent提案与并行评分

日期：2026-11-04。用户已明确授权本聊天agent并行；本文件只细化计划，没有运行拟合、评分、solver或独立audit/dryrun，没有读取gate/test。

## 角色与权限

|角色|并行职责|输入边界|唯一写入产物|
|---|---|---|---|
|root协调者|固定数据版本、分配任务、合并完整反馈、推进轮次|允许的fit/feedback；独占gate控制|轮次状态、预算账本、经验记录、最终候选|
|提案agent A|每轮提出1个长度/符号或其交互规则|相同fit摘要和上一轮已完成反馈|该轮candidate_A.json及理由|
|提案agent B|每轮提出1个图/门或聚类启发规则|与A相同版本；不可见本轮未完成分数|该轮candidate_B.json及理由|
|评分worker|并行拟合/评价两个候选和匹配容量普通小树|冻结fit、完整feedback、统一计分代码|按候选/版本隔离的逐题预测与指标|

角色是分工，不要求每轮重新创建agent。root可复用已完成任务的agent；worker也可为进程而非LLM，不额外消耗提案配额。只有root更新主状态和预算，子任务不竞争写同一文件。

## 轮次配额

- 每轮所有agent合计最多2个提案，A和B各1个；并行不把限额变成每agent各2个。
- 本分支最多4轮，计入全项目最多8轮的剩余额度；已有正式episode先扣除，不另起计数器重置额度。
- 每个候选最多2项数值特征、深度2，阈值仅取fit七个分位，每叶至少12个不同父实例；缺失回退固定策略。
- 旧未评分提案保持未评分。若旧任务仍占同一轮额度，由root先明确分支/轮次映射，再派发本轮任务。

## 可重叠的工作

固定输入和fit特征快照后，可同时启动普通小树训练、k2/k3聚类、A/B两份提案准备。聚类只在fit拟合变换与中心；结果尚未完成时，A/B可先用已冻结静态描述提出首轮规则。

动态observer准备可以与上述工作重叠。fit收益空间通过计划门槛、实现与资源资格冻结后，40题短探针及条件性扩展可与静态ICL轮次并行；它不必等待所有静态轮次结束，也不占用静态评分器的标签生成流程。

聚类结果或动态结果若在本轮提案冻结后到达，只能进入下一轮的输入版本；不回改本轮提案。动态数据齐备后才建立静态/静态+动态的同人口配对评价，不从已完成的部分feedback单元提前挑有利案例。

## 必须保留的屏障

1. **输入屏障**：root冻结split/等价组、成本约定、TA标签SHA、特征定义与可用性、fit变换、计分源码和轮次编号。各评分任务接收相同版本。
2. **提案屏障**：A/B两个JSON及控制方法同时提交后，才放行本轮新feedback评分；任何agent不能先看A的成绩再改B。
3. **完整评分屏障**：候选A、B、普通控制可并行计算，但都须在相同完整feedback人口上保存逐题预测、缺失回退和费用。部分结果只记执行进度，不反馈给提案agent。
4. **反馈屏障**：root核对必要输入/结果身份后一次性生成完整episode，保存两个候选的正负reward、尾部损失和拒绝理由，再向A/B发布相同反馈版本。
5. **下一轮屏障**：本轮episode完成前不进入反馈驱动的下一轮。可预先准备无反馈依赖的代码/数据，不能将其称为下一轮已学习提案。
6. **最终屏障**：先冻结一个候选及对照，再由root一次性使用gate。所有提案agent及普通节点均无gate/test访问权，结果不回流上下文。

必要身份核对并入正式执行，不另起独立审计或dryrun。相同固定对照的已完成评分可按输入/源码SHA复用；不为每个agent重复计算同一基线。

## 静态与动态比较

动态量来自固定D前缀，标签仍为TA已有false/true wall time。所有180fit/60feedback父题保留，观测缺失者回退同一静态规则，不用不同子集比较成绩。

至少比较静态规则、同容量静态+动态规则、同容量普通树。动态提案仍占该轮最多2份的总配额，不因增加特征再开两份“免费”候选。探针CPU与TA wall分列，未校准时仅报告预测增量及盈亏平衡开销。

本聊天多个agent具有共享历史，不是独立抽样的第二LLM，也不是严格的无记忆对照。对照使用明确冻结的普通小树；若无真实独立实验，不声称ICL记忆的因果优势。

## 关键路径与估时

最小路径为：输入冻结 → 并行首轮提案/基线/聚类 → 并行完整评分 → root完整反馈 → 后续反馈轮次 → 唯一候选冻结 → 一次gate。

每轮时间按 `max(A提案, B提案, 必需控制准备) + max(A评分, B评分, 控制评分) + root合并` 估计，不把独立任务用时相加。总时间近似为共享准备加上 `max(静态迭代支路, 动态采集支路)`，再加必须等待的动态融合轮和最终留出；仍须计入轮间顺序反馈。

开始执行后用每个任务的排队/运行/传输/合并时间更新ETA。当前只承诺计划中的预算和停止条件，不把agent数量当线性提速倍数；服务器已满载时，本地提案并行也不会凭空产生远程worker槽位。
