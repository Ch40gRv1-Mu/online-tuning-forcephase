# Forcephase 工作流：先取得可判别证据，再扩大投入

## 2026-11-04 效率修订：适用于后续调度与新协议

本节回应用户对超过24小时低效研究的复盘请求。依据见 `WORKFLOW_REVIEW_20261104.md`。它约束后续工作方式，不追溯修改已冻结的样本、评分、成功门槛、配置或在途任务。后文H01–H06是已完成历史研究，不是所有新分支必须重走的流水线。新CaDiCaL研究与TA复用分支遵从各自更具体的冻结协议；既有完整矩阵/最低轮数要求不能用本节绕过。

### 1. 先确定当前要回答什么

每项新研究用一个简短协议写清：问题、数据角色、可复用结果、唯一主对照、主指标、第一正式块、信息不足/继续条件、CPU与墙钟预算、owner、下一份交付。不为每个常规步骤建立新审批或新文档层；协议和执行源码可一次提交。获授权后直接推进，解释用户的追问不替代实际工作。

|层次|要回答的问题|最小交付|何时增加成本|
|---|---|---|---|
|预测证据|限定少量变量后的相对配置偏好能否预测父题偏好？|允许开发数据的父级预测、弃权覆盖、与固定/多数策略的配对比较及不确定性|现有样本无法区分信号与噪声，且下一块预期能增加有效父标签|
|机制/特征|长度、符号、连接或短传播量是否增加选择信息？|同一人口、同一容量简单模型下的增量与反例；免费特征收益和实际采集费分列|简单基线留下明确未解释问题|
|部署|收益能否支付探测、构造、切换及求解成本？|冻结一个候选后的真实端到端结果|开发证据达到该分支既定晋级门槛|

不能用“探测太贵”否认已经观察到的预测信号，也不能用覆盖子集的高准确率声称可部署。以D/F+/F−的成对相对成本或赢家/弃权检验偏好，不用子父绝对耗时相关代替。不同条件分支、seed和重复计时不是新的独立父样本。

### 2. 信息产出优先于原始题量

先复用允许开发数据做固定对照、免费oracle和删失分析，再决定是否需要求解器调用。缺结构量时仅补提取，不默认重跑完整配置矩阵；兼容性必须绑定输入、版本、配置、seed、预算、计时/验证方式。TA两方向数据不能补造D或替代另一solver的新测量。

新协议必须在执行前指定：首块的固定名单/顺序、有效偏好标签所需覆盖、oracle空间相对目标收益的下限、零/低decision与缺失处理、继续或停止条件。可参考24–40父题，但实际首块大小还必须适合其预算和30–60分钟反馈窗口；不为凑题数排入数小时批次。已有固定面板不能回头删掉难题。

每个完整正式块记录 `N_parent / N_cost_valid / N_clear / N_all_censored / N_unverified`、新增物理CPU、墙钟、每CPU小时有效标签数和oracle空间。必要时记录有信息的动态观测数。合法完整fit块可按预设条件作可行性决定；feedback只按其原协议完整评分，gate/test不用于排障选题或提前止盈。

若大量双/三超时、oracle空间不足，或短子题只有解析/预处理计时，停止自动扩大同类设计。按预设条件保存范围明确的负结果/证据不足；下一协议可采用已有外部难度参考选定可测层、单独预算层或更廉价观测。保留原广分布面板并说明人口变化，不能按当前赢家补题或混合T60/T600标签。分类未知仍可贡献删失下的成本证据，不得一概丢弃。

### 3. 缩短反馈循环，避免长实验先行

新发现阶段默认顺序：**复用标签/特征 → 一个简单对照和有限候选 → 完整开发评价 → 必要的定向补采 → 一个候选的部署/留出**。聚类、ICL和遥测是可选的方法，不能替代成本敏感浅规则基线。相同成本矩阵上的新候选优先离线评分；有噪声疑问先做有界、配对的必要复测，不能用成千上万次重复制造有效样本量。

- 准备输入和缓存可用后，首份可计分比较目标30–60分钟；时间必须从任务实际开始记录，另列输入准备等待，不能靠反复重置起点隐藏耗时。
- 首块若预计不能在该窗口完成，在冻结前缩小该块或先交付已有标签的基线/选择空间。若只有长测量才能回答问题，先报告其必要性和完整时长，在既有授权内推进；不能把目标时间当作截断证据或强造正结果的理由。
- 连续两小时没有可计分比较时，必须写明阻塞环节、已经完成的实物、剩余关键路径和更便宜的授权内替代动作。预算/数据/成功标准的实质改变需先版本化；不要机械等待heartbeat或再交一份泛化方案。
- 若简单离线比较已经得到范围明确的否定答案，及时交付。只有预设继续条件满足，才追加大矩阵、多seed、在线observer工程或真实部署。已有冻结的最低轮数/完整矩阵要求继续执行，除非用户改变要求；不得伪造已完成状态。

### 4. 资源、ETA与所有权

在正式执行时把可用核、任务内存/证明空间、磁盘底线、已有占用与真实worker数记入receipt。合理利用现有8CPU；资源只容许2worker时先解释具体瓶颈，并在不破坏计量可比性的前提下规划未开始任务。不能让低利用率悄悄持续，也不能无视内存直接开满。换机器或改资源profile须绑定新身份，不掩盖计时差异。

`剩余CPU工作量 / 实际可持续worker数` 仅是计算部分估计；完整ETA另含准备/下载、排队、检查、导入和分析，优先用已完成单位的端到端吞吐给区间并标注观测时间。320×60/8=40分钟不能被表述为完整研究40分钟完成。把物理CPU、复用的逻辑成本、保守预留分列，避免重复记费。

一个实验一个owner、一份claim/完成账本。继承现有健康队列、持久化每个完成单位；观察失败标记未知，不重提在途工作。不因读到旧handoff或另一个SSH地址而新建worker。正常检查随正式执行进行，不另开audit/dryrun。当前无本轮新实验授权；本次复盘不启动、终止或重排服务器队列。

无需等待整个远程长队列才做无依赖的本地开发分析，但只能使用获准且完整的数据角色。显式允许并行时可分配不相交的任务，所有任务共享同一预算和反馈屏障；其他工作不继承该授权。禁止跨聊天发消息。

### 5. 单一入口与简短交付

根AGENTS是路由入口：旧H01–H06状态、新CaDiCaL子项目和TA复用分支分别标明适用范围，不互相代替。原owner更新其状态与tracker；旁路解释不复制一套活动状态、不改实验结果。已完成轮次不自动重开。

进展只需：已完成什么、有效信息多少、费用/瓶颈、下一结果何时到。新结果优先给逐题/汇总表和一句结论；用户要求的HTML、图片或完整包随后提供，不把排版当成核心证据的前置条件。主动工作时保持简洁沟通，长期任务状态未变时按现有有意义变化通知规则执行，不重复广播轮询。

每次交接保存原owner/阶段、完成与剩余单位、证据路径、下一条可执行动作及阻塞条件。优先更新已有状态/执行表，历史材料按需读；禁止每轮从所有文档重新调查。负结果本身是交付，计划、commit数量与solver调用数不是研究进展的替代品。

# 历史冻结协议：寻找能持续有效的简单选择信号（H01–H06，已完成）

目标：输入一个原始 CNF，用少量、廉价、可解释的特征决定 D、F+ 或 F−；证据不足时回退 D。可以只找到“何时选择 F−”这样的局部适用规则，不要求强行覆盖三类。成功结论必须限定适用题型、预算和覆盖率。最终也允许得出“本轮候选没有足够证据”的否定结论。

## 固定研究问题与标准

绝对耗时的父子相关、配置相对速度相关、选择赢家准确率、实际净收益是不同统计量。主要优化目标是 **特征/探测成本 + 所选原题配置成本**，对比开发集预先选定的最佳固定策略 D；同时列出 F+、F− 和 oracle。超时按相同 60 秒预算下 PAR2=120 记分，不能把它当实际消耗；真实 CPU、墙钟、验证成本和失败消耗分别记账。额外准备/探测时间直接加在 PAR2 外；最终部署需用共同端到端预算再实测，不能把回放当真实调度完成。

主要成功门槛（本轮预先设定，不能看到确认结果再放宽）：

1. 新确认集总成本 / 固定 D 成本 ≤0.99，按 family 聚类 bootstrap 的 95% 上界 <1；真实 CPU 与 PAR2 分开报告。覆盖新题两个固定区块时，各区块点估计均 <1。1% 是本轮最低实际收益门槛，不是已发现的效应。
2. 在有明确赢家的题上，整体选择准确率相对 D 至少提高 5 个百分点，配对 family 区间下界 >0；明确标签沿用胜过其他配置 `max(0.02秒,最快耗时×10%)`。三者未解、近似平局、验证失败分别保留，不能强行造标签。
3. 非 D 规则在明确标签中的覆盖率 ≥20%，覆盖 ≥20 道明确题和 ≥5 个家族；触发后的正确率 ≥75%，95% 下界 >50%。对每个实际声称能识别的 F+/F− 类分别报告，不把合并准确率作为每类准确率。
4. 种子 0/1/2 均保留净收益方向，seed0 独立重跑用于区分计时波动；在这 4 次测量中明确赢家的一致率 ≥80%。未通过只称候选，样本不足称证据不足。
5. 对新 family 单独给结果；若不足 10 个新家族或没有正向净收益，禁止声称“跨新家族稳定”，即使同家族新题成功。达到前四项仍可给有明确分布边界的结论。

这些是研究筛选门槛，不保证能找到有效规则。现有数据 oracle 对 D 的 PAR2 空间仅约4.4%，需要控制任何额外开销。所有已看过的数据都是探索数据；后续确认只检验最终冻结的 **一个** 候选，避免反复挑选确认集赢家。

## 数据与评估

- 现有300题只作开发：69明确赢家、46明确标签家族、291有效成本三元组；新增252题中的200题三配置都超时。后续不以原始 N 代替有效标签数。
- 用 family 分组的外层交叉验证评估完整训练程序；阈值和特征选择仅在训练家族内进行。family/isohash 相同的题禁止跨训练/测试；输入清单已有 isohash 去重，仍在新数据筛选中全局排重。
- 样本不足优先报告，不盲目提高所有超时。需要更长预算时先单独冻结统一的预算敏感性协议，标记新的任务定义，不能与60秒标签混合。
- 确认前冻结规则、提取器、数据清单、配置和分析程序。最多160个新父题，40题/块，优先新家族且按家族轮转。每块开始前确定固定顺序，不按当前赢家补题。全部候选选定后才运行确认标签；不能边看确认结果边调整规则。
- 确认前把160题固定分成两个80题区块；只在全部完成后进行主要检验。40题块仅用于执行恢复、资源估算和有效性记录。若资源不足以完成预定样本，保留为不充分证据，不提前宣布显著。
- 低标签覆盖时可建立独立“可测难度分层”探索样本，但只能用外部既有基准时间或预先固定、计入成本的筛选规则；必须保留原广分布面板，明确结论人口改变。

## 两层循环

内循环：读状态 → 选一个假设 → 写 protocol.md 并提交 Git → 正式运行 → 核对行数/身份/验证状态 → 输出所有折、成本与区间 → 写 analysis.md → 更新状态。每个假设只允许一个事先列出的主模型和有限的训练内参数；新想法另开带时间戳的探索条目，不伪装预注册。

外循环：每完成2个假设，比较效果、触发覆盖和开销，寻找失败原因；有信号则检验机制，无信号则转向下一类。最多6类，不做无上限阈值搜索。最多1个候选进入新数据确认。若6类均无可用候选，输出否定总结并结束本轮研究；若确认失败，不再用同一确认集改规则。

计划假设，按便宜到昂贵推进；每项执行前仍需冻结具体实现：

| 编号 | 简单信息 | 要检验的解释 | 正式探测边界 |
|---|---|---|---|
| H01 | 原有13项静态特征，一次阈值、允许回退D | 少数可解释区间能降低误选成本 | 复用现有特征；分别评估零特征开销上界和现有完整提取器实测成本 |
| H02 | 正负号结构：纯正/纯负子句、按长度加权的全真/全假未满足比例 | 决策初始方向与符号约束的不对称有关 | 提取最多1 CPU秒/题；超限即弃权，开销照计 |
| H03 | 根传播前后剩余变量、二元子句与正负不平衡的变化 | 原始计数被会立即消失的约束掩盖 | 提取最多1 CPU秒/题；不能用答案作为预测特征 |
| H04 | 原题D的极短轨迹：冲突/决策/传播速率、已求解标记 | 原题动态信号比删子句更接近目标 | D探测0.1 CPU秒/题；0.3秒为预先列出的训练内备选，总成本入账 |
| H05 | 原题F+/F−极短探测的相对进展 | 方向响应早期可区分大幅退化 | 每配置0.1 CPU秒；0.3秒仅训练内备选，不继承长跑终局信息 |
| H06 | 固定一个变量后纯传播的差分、分支不对称 | 条件子题保留结构且只用传播能降成本 | 3对互补赋值，合计0.3 CPU秒；不重复5秒×多分支的昂贵选择流程 |

模型限制：最终规则最多2个特征、最多2层；优先单阈值。H01先只用单阈值，至少8个训练题和4个家族支持一个切换叶子。无法观测特征或证据不足则回退D。禁止用family名称、题目ID、来源年份、SAT答案作为部署特征；family用于分组和分析。

探索进入确认的条件：完整外层预测成本点估计优于 D，至少有一个非D叶子达到支持门槛，效果不由一个家族单独贡献，且开销后仍有收益空间。该门槛只决定是否值得确认，不等于显著成功。

## 执行、资源与连续性

8CPU动态补充独立任务，1 worker/逻辑CPU、每进程1536MiB；复用已验 CaDiCaL 与 LRAT 检查器、完整 CNF 与哈希。正式 parent 60秒、额外10秒墙钟看门狗；模型/LRAT检查沿用60CPU/70墙钟；临时证明1GiB，上限/验证失败不能算 solved。磁盘保留16GiB。短探测必须使用实际支持的CPU/冲突限制并记录实际CPU，不能把整数墙钟限制冒充0.1秒CPU限制。

遵从“不做audit和dryrun”，不另起独立审计、不重测已验证基线；协议锁定、正式模型/证明验证、输入完整性及基本结果核对直接并入执行。每个正式块最长规划2小时，按完成单位写盘、避免重复工作；上传完成后才执行。CPU、验证、准备、探测与失败消耗都累积记账。

继承运行配置总50CPU小时是保守调度边界，其来源是旧config，不凭此声称用户刚批准了50小时。当前累计快照69452.23CPU秒（约19.29小时），执行前刷新；每40题或每假设重新估算。达到规划边界时保存状态并总结证据/剩余工作，不因助手估算变化自动索要权限，也不悄悄扩充题量和预算。真实资源限制有明确来源才称硬限制。

每20分钟本聊天 heartbeat 读状态并继续；运行中只检查已有任务和完成单位，空闲时执行下一正式步骤。状态不变不通知。实质结果、失败、需输入或完成时报告。通知只在聊天；历史一次总结邮件不授权持续邮件。完成成功或本轮否定条件后，记录最终结果、将goal标记complete并暂停本研究heartbeat；不能仅因设置完成而称研究成功。
