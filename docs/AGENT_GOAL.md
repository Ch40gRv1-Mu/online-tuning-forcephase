## 3. P0：让无效数据不能进入训练和正式分数

### 3.1 明确分类，不再静默补齐

建立机器可读的完整性审计，至少检查计划实例集合、唯一 `(instance, seed, config, track, K)` 键、版本/二进制、CNF、预算、运行状态、遥测 schema/结束状态、配对覆盖与实际动作。

- **合法未到决策点**：完整运行证据支持在所需自然 restart 前已解出，或预算内未达到该点；单独标记原因，保留全体实例的部署计分，不伪造训练标签。
- **遥测文件缺失/损坏、缺 replay、base 缺失**：是数据错误，不能用 baseline 成本回填后继续产出完整分数；给出 run_id、原因、补采/补跑清单，正式分析默认硬性失败。
- **可产生监督标签的同状态配对**：必须 prefix digest 一致，检查点/方向/轨道正确，切换确在指定自然 restart 应用，且次数与配置相符。不一致时查明原因并补跑；不能只统计 mismatch 后照常训练，也不能选择性删掉不利样本。
- **预算边界双超时例外**：现有三例在 K=1e5，某分支未到检查点，两边均 timeout、终端罚分均为 600。核实后单列为 `censored_unmatched`，训练权重为 0，不声称 digest 已通过。全体实例的终端评分可保留已观察到的双超时罚分；需要同状态证据的统计不能把它们当有效配对。不得把此例外推广到非双超时或其他缺文件。

输出逐组清单：总实例、合法未到达、有效配对、双超时无匹配前缀、missing、mismatch、实际切换、正权重标签。所有报告给出自己使用的精确分母。

### 3.2 有针对性的回归验证

验证缺文件、截断 JSONL、重复键、缺 alt、digest 不同、方向错误、应切未切、合法预处理解出、合法阈值前解出、预算边界双超时。保证错误路径会阻止正式分析；这些验证应检验科研有效性，不能只镜像函数实现。对现有数据跑完整审计，保存结果和例外列表。

## 4. P1：修复观测语义，并完成唯一的 M3 科学纠正

### 4.1 控制器修复规范

- checkpoint 和 window 各自维护上一条**同类记录**的相位历史。翻转率分母只计前后均有效、仍对应同一变量的样本；没有可比较历史时为 `null`，不是 0。
- 同一 restart 同时触发两类记录时，先捕获同一份 pre-action 状态，分别算两类特征并各更新一次历史，再执行当前模式至多一次动作。不得出现 checkpoint 已切换、window 却被称为同一动作前观测。
- 处理 compaction 的身份变化。最小可行实现：检测压缩事件，重建固定大小样本并同时失效两个流的历史；各流第一次压缩后记录的 flip 为 `null`。也可显式跟随变量映射，但必须验证身份。不能把重新编号当作极性翻转。
- 样本 RNG 与动作 RNG、solver RNG 分离；保持 O(固定样本数) 的特征开销，不能每决策扫描全变量。
- 加小型行为验证：同 hook 两记录、连续同类记录、真实翻转/不翻转、压缩后历史失效与重建、不同记录组合。确认 controller-off、telemetry-only、fixed、原冻结 schedule 不额外改变决策/冲突轨迹；保留 API phase/传播/证明优先级。修后新 schema/二进制与旧数据显式区分。

### 4.2 使用既有轨迹复算，先不重新采全集

本轮唯一固定纠正为：**在旧开发数据中统一排除 `x_saved_flip_frac`**，包括 P_GROUP、all、shuffled-label 对照、单变量信号/相关性及解释图。旧日志没有可恢复的逐变量历史，禁止用两个负比例之差“补算”flip；禁止混合新旧遥测。

其余数据、标签、K={1e3,1e4,1e5}、两种 prefix、特征组、模型网格、种子、评分方式和模型容量保持原设定。直接加载并验证原 `reports/m3/folds.csv`；外层 family membership 不变，内层实例集合和生成种子不变。删失/零权重行先保留原 fold 归属，不能因过滤行而重新分配家族。缺失值填充、缩放和模型训练只在相应训练折拟合。

先复现原表，再运行修订流程。报告所有预定组的原/修订 OOF PAR2、solved、按家族区间、相对 D/I−/static/time-only/shuffled 的差异，不只展示较好的组。未依赖坏特征的结果应在合理数值容差内复现；发现差异须解释。针对修订模型校验 Python 与 C++ 导出的分数、缺失处理和动作一致性，特别检查含 CPU 时间模型的计时敏感性。新策略文件用新路径，不能覆盖冻结 M5 文件。

修好的 flip 可在小型开发子集验证，但完整重采正确 flip 不是收尾必选项。若将来要用它训练新方法，另订数据和评估协议。

## 6. 科研结论如何完成，什么时候才需要新实验

修正后用条件清楚的表回答四个原问题：

1. **何时负分支有利/有害？** 给出所有家族的完整效果，另选预先说明规则的获胜与失败实例解释。区分初始负、全程强制负、decision-only、rephase 关闭和早期负 prefix。符号翻转的证据只支持相应编码/子集，不外推为全部获胜家族的原因。SAT/UNSAT 只能事后分层，不能作部署时已知输入。
2. **哪些在线观测有用？** 用纠正后的特征组比较和校准/成本敏感结果回答；区分家族间相关、家族内预测、真正的未见家族性能。没有收益时只能说“这些数据、预算、特征和模型未找到可迁移信号”，不能说在线信息普遍不存在。
3. **是否需要反复切换？** 分开说明时机 oracle、固定调度、一次选择、mode-only 与尚未实施的内容驱动重复选择。若原门槛仍不满足，记录“不继续该分支”的证据；不能把未实施的方法写成已被否定。
4. **机制和开销是否解释得住？** 核对消融是否只改变声称的因素；不能把非匹配配置的差异全部归因于 rephase，也不能由相关性宣布因果。若已有控制组不足，优先收窄措辞；确需补小型开发消融时先固定配置、样本与预算。

**若纠正后仍无可靠收益，完成限定性的负结果即可结束本研究。** 原 M5 主假设失败保留，不因修订挑选新的 test winner。无需为了看起来复杂而实现 bandit/RL，或自动重跑长 cutoff 全集。

若纠正后出现可能改变结论的开发集收益，只能称为事后开发发现。先写明模型/规则、主要指标、样本、compute 和停止条件并冻结，再使用真正未见、与所有既有数据去重且按家族控制的新评估集；旧 test/t2026 只能作为事后复现。选样不能依据新方法是否获胜。不具备独立数据/预算时，交付候选和未验证状态，不把开发集收益写成泛化结果。本轮主收尾不以此扩展为必要条件。
